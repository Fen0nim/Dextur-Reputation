# Обновление до 1.0.0

1. Остановите всех writers: Paper, второй сервер, StorageAdmin и внешние скрипты. Не запускайте новую и старую версии одновременно.
2. Сохраните полный каталог плагина, выбранную БД, schema history и обе локали. Отдельно сохраните LuckPerms. Проверьте контрольные суммы и возможность чтения копии.
3. Замените основной JAR на 1.0.0. Сохраните scope, storage.type и пути. Flat storage.yml v1 без selector продолжает использовать MYSQL. Новые установки используют JSON.
4. Запустите один сервер. JSON читает исторические форматы 1–7 и выбирает формат записи по сохранённым разделам; SQLite и MySQL/MariaDB применяют последовательные схемы до 7. 1.0.0 не добавляет V8. V1–V7 остаются неизменными.
5. Проверьте профиль/язык, историю и pending, приватный inspect, Trust, tier/hysteresis, recovery/rewards, policy/admin contribution/locks, audit и bulk status. Совпадение только visible score недостаточно.
6. Перезапустите ещё раз и повторите проверку. Bulk с сохранённым cursor не продолжается автоматически; проверьте status и явно resume/cancel. Confirmation tokens живут только в памяти и после рестарта недействительны.

Существующие YAML не переписываются. Недостающие новые поля берутся из поставляемых defaults в памяти, custom значения сохраняются. Неверные типы/версии/пересечения правил приводят к диагностике, не к замене файла. Все файлы, кроме features.yml, требуют restart.

При ошибке остановитесь, сохраните повреждённую/обновлённую копию отдельно и восстановите **весь** pre-upgrade backup с соответствующим старым JAR. Не пытайтесь понизить schema-version вручную. Старый writer не поддерживает более новый формат. Ни rollback, ни смена storage.type сами по себе не переносят данные.
