# Контрольные измерения 1.0.0

Linux amd64, 4 CPU, лимит памяти cgroup 32 GiB, Java 25; тестовая куча до 2 GiB. SQLite, MariaDB 11.4.8 и MySQL 8.4.7 работают локально и проверены отдельно. Лимит JSON по умолчанию — 64 MiB. Время измерено через nanoTime; p95/p99 рассчитаны по отсортированным выборкам методом nearest-rank. Отдельного прогрева нет: настройка и импорт выполнены до измерений, первое измерение сохранено. Кеши и соседние задачи сборки могут влиять на результат. Гарантии production TPS/SLA нет.

Большой синтетический набор: 10 000 профилей/100 000 голосов, 3000 записей аудита, 500 модераций и 1000 флагов. После реальных операций pending/recovery/admin перед измерениями — 10 301 профиль/100 200 голосов; после новых голосований — 100 300 голосов. JSON отклоняет большой набор по стандартному лимиту. Его замеры относятся к отдельному малому набору (до 100 голосов), поэтому прямое сравнение с SQL некорректно. Для JSON запрос страницы 3500 возвращает пустой результат. Замер GUI относится к неизменяемой модели отчёта; отрисовка предметов Bukkit и клиентом не измерялась.
